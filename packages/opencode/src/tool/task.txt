Launch a new agent to handle complex, multistep tasks autonomously.

Available agent types and the tools they have access to:
{agents}

When using the Task tool, you must specify a subagent_type parameter to select which agent type to use.

When to use the Task tool:
- When you are instructed to execute custom slash commands. Use the Task tool with the slash command invocation as the entire prompt. The slash command can take arguments. For example: Task(description="Check the file", prompt="/check-file path/to/file.py")

When NOT to use the Task tool:
- If you want to read a specific file path, use the Read or Glob tool instead of the Task tool, to find the match more quickly
- If you are searching for a specific class definition like "class Foo", use the Glob tool instead, to find the match more quickly
- If you are searching for code within a specific file or set of 2-3 files, use the Read tool instead of the Task tool, to find the match more quickly
- Other tasks that are not related to the agent descriptions above


Usage notes:
1. Launch multiple agents concurrently whenever possible, to maximize performance; to do that, use a single message with multiple tool uses
2. When the agent is done, it will return a single message back to you. The result returned by the agent is not visible to the user. To show the user the result, you should send a text message back to the user with a concise summary of the result. The output includes a task_id you can reuse later to continue the same subagent session.
3. Each agent invocation starts with a fresh context unless you provide task_id to resume the same subagent session (which continues with its previous messages and tool outputs). When starting fresh, your prompt should contain a highly detailed task description for the agent to perform autonomously and you should specify exactly what information the agent should return back to you in its final and only message to you.
4. Use background=true when you want to start a subagent asynchronously. This returns immediately with a task_id while the subagent keeps running in the background.
5. After launching a background subagent, prefer ambient waiting: continue with other work and let Selene surface important milestones automatically. Use task_status, task_watch, or task_cancel only if the user explicitly wants task internals or manual control.
6. For high-uncertainty work, use task_branch to run 2-5 counterfactual strategies in parallel and pick a winner. Prefer ambient branch tracking by default; use task_branch_status for manual inspection and task_branch_apply to safely apply the winner back to the parent workspace when needed.
7. Background tasks and branch runs publish shared context updates into the root session tree. task_status, task_watch, and task_branch_status remain available for power-user/debug detail, but should not be your default conversation loop.
8. If sibling tasks or branches disagree, use task_context_reconcile with the shared context entry ids to publish an explicit authoritative resolution for future sessions.
9. Use task_coordinate for directed sibling collaboration and handoffs. Use shared context for broad publishable results. Prefer task_coordinate when one sibling needs a specific answer, claim, or resolution from another.
10. Subagent coordination is asynchronous. Do not wait indefinitely for another sibling; continue with best effort, publish gaps, and escalate conflicts or deadlocks to the parent.
11. The agent's outputs should generally be trusted
12. Clearly tell the agent whether you expect it to write code or just to do research (search, file reads, web fetches, etc.), since it is not aware of the user's intent. Tell it how to verify its work if possible (e.g., relevant test commands).
13. If the agent description mentions that it should be used proactively, then you should try your best to use it without the user having to ask for it first. Use your judgement.
14. The harness may send synthetic follow-up reminders when a background task, branch run, or sibling coordination update reaches a useful milestone. When that happens, inspect the latest shared context and collaboration updates, continue proactively, and only mention low-level task tools if the user wants manual control.
